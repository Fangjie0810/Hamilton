# Hamilton 项目约定

## 中英文同步（用户于 2026-09-08 明确要求）

- 所有新增或修改的玩家可见文字，必须在同一改动中完成中文和英文，包括剧情、选项、角色说明、玩法说明、动态反馈、结局，以及未来美术素材中的文字。
- 使用 `src/i18n/text.ts` 的 `bi(中文, English)` 配对维护。剧情字段使用必填 `BiText`，不接受只填一种语言或空白占位翻译。
- 动态文字用 `f(bi('中文 {0}', 'English {0}'), value)`；中英文使用相同参数。中性分隔符拼接用 `cat`，不能把双语对象直接插入普通模板字符串。
- 普通 DOM 显示用 `setText` / `setLabel` 或现有 `element` / `el`，只显示当前主语言；对话正文用 `setDialogueText` 显式渲染双语字幕，不要绕过语言更新机制。三维舞台招牌等非对话文字也只显示主语言；切换语言不能重开章节、重置对话或改变小游戏计时和成绩。
- 默认模式为 `dual`（双语 · 中文主字幕），另有 `dual-en`（双语 · 英文主字幕）、`zh`、`en`，并保存偏好。双语仅涉及对话语言；按钮、选项、角色说明、玩法说明、非对话小游戏、状态反馈、幕间标题和结局等跟随主语言单语显示（用户于 2026-09-13 明确要求）。检查四种模式及两种双语的小窗口布局。
- 语言选择按钮及选项是上述界面语言规则的特例：始终用目标语言自身命名，即「双语 · 中文主字幕」「Bilingual · English first」「中文」「English」，不随当前界面翻译（用户于 2026-09-13 明确要求）。源文案仍成对维护，并标注对应 `lang`。
- 若图像中必须包含文字，应同步准备中文和英文并按主语言展示；对话字幕另由界面支持中英主次切换。可变字幕优先由界面渲染，避免烘焙到图片中。
- 提交前运行 `npm test` 和 `npm run build`。构建包含 `check:i18n`，禁止跳过或削弱漏译与模板参数检查来通过验证。

## 执行与验证

- 复用现有状态系统、章节检查点和玩法生命周期，不为语言切换重新创建游戏。
- 尽量保留既有玩法参数。幕间普通渐入/渐出为 550 ms，标题等待 2875 ms；减少动态时为 250 ms 简化等待。
- 日常脚本使用 npm，依赖仍以 `pnpm-lock.yaml` 为准。浏览器回归说明见 README。
- 若信息缺失会影响实现决策，应简洁说明缺少什么及原因；能够独立解决的运行与验证由开发代理完成。

## 人物美术分层（用户于 2026-09-14 明确要求）

- 对话框上方的人物立绘称为「主像素美术」，需要比场景人物更精细；游戏中跑动的角色称为「Q 版像素美术」。后续讨论与素材命名使用这两个称呼。
- 用户认为第一轮四组主像素样稿游戏感与动作张力不足；保留于 `art-direction/main-pixel-studies-2026-09-14/` 仅作历史探索，不视为选定风格。
- 用户已确认 Eliza 画法与 `art-direction/main-pixel-action-studies-2026-09-14/` 中 Hamilton/Lafayette 动作方向。正式主像素美术位于 `public/art/main-pixel/v1/`，10位角色共59帧；`src/data/mainPixelArt.ts` 记录逐角色实际朝向、图集位置和态度语义，不能假定生成图都朝向同一侧。
- 逐句态度依据 `docs/art/main-pixel-reaction-audit-2026-09-14.md`，由 `src/data/dialoguePerformance.ts` 精确映射台词；新增台词需审查说话、句后和听者态度。普通开口使用基础绘制帧，句后独立闭口反应持续保留；不要把暂停／缓冲误当台词结束，也不要给严肃剧情强加大笑。
- 抠像与边缘颜色恢复统一使用 `src/ui/portraitPixels.ts`，保留生成原件，不另写简化阈值抠像。正式全部帧检查页见 `art-direction/main-pixel-production-2026-09-14/`。

## 唯一游戏主流程（用户于 2026-09-09 明确要求）

- 三维游戏是唯一主流程；不再使用、维护或新增横版 2D／经典版。后续玩法、配音、设置与回归都以三维主线为准。
- 横版 2D 专用入口、实现和 Phaser 依赖已退役；旧 `?story=2d` 链接转入 `?story=3d`。共用剧情、状态、小游戏和已生成素材继续复用。

## 子域名版本管理（用户于 2026-09-10 明确要求）

- `ham.newflorencia.com` 首次线上测试版定为 `0.1.0`；后续统一以 `package.json` 为版本来源，替代旧内部版本标识。
- 每次用户要求发布更新时升级版本、更新 `CHANGELOG.md`，执行 `npm run release:pack -- --notes '具体变更'` 并保留网站及源码归档。
- 服务器版本独立保存在 `releases/<version>/site`，通过发布工具切换 `current`，禁止直接覆盖已归档版本或直接向 `current` 写入文件。
- 本地开发不自动上线；发布、校验、切换与回滚遵循 `docs/版本管理.md`，正常发布不修改其他子域名。
