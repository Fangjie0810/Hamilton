# 《My Shot》网页音游：音频分析与第一版谱面

日期：2026-10-28。范围：独立单曲试玩；与主游戏旧小游戏设定无关。

## 这版谱面打什么

先让反复听原声带的玩家用双手找到熟悉的脉搏，再在清晰的八分起音上加键。主拍形成可记忆的四拍手型，第二组乐句保留相同手型或镜像；强烈的乐句开头偶尔双押，音色变稀疏的段落保留空隙。**这版没有把每个说唱音节都变成按键，也没有逐字歌词谱。**

所有音符为 tap，键位 D / F / J / K，四轨下落和圆点浮现共用一份绝对时间谱面。

| 难度 | 音符总数 | 最密一秒 | 八分插入 | 双押 | 首音 / 末音 |
| --- | ---: | ---: | ---: | ---: | --- |
| 入门 | 341 | 2 个 | 0 | 0 | 2.3568 / 328.3940 秒 |
| 标准 | 639 | 5 个 | 176 | 23 次 | 2.3568 / 328.7423 秒 |

入门采用每四拍 2～3 次敲击，在空隙中听音乐。标准谱保留主拍，依据信号挑选八分起音，每个四拍单元最多插入两次八分音符；手型不会随机变化。第一音前保留约 2.36 秒，收尾衰减不再出键。

## 节拍结论与证据边界

主速度估计为 **约 91 BPM**，相邻主拍通常间隔约 0.66 秒。对全频人声直接运行通用节拍追踪，会在密集说唱处产生半拍/倍速跳动；因此最终采用 2.4～10 kHz 起音变化，辅以连续性约束。

输出 **503 个逐拍时间点**，首个追踪脉冲为 0.3251 秒。第一脉冲仅是算法相位原点，**不是已经人工确认的小节第一拍**。实际第一颗可玩音符在 2.3568 秒的清晰起音上。

`tempoMap` 每 16 拍计算一次平均速度。大部分完整伴奏段约 90～91 BPM，过渡段存在更大的估计变化。它包含录音时序差异，也可能包含稀疏段的追踪误差，**不能据此宣称原曲每一处都正式变速**。前端直接使用 `notes[].time`，不要用显示用的 91 BPM 重建整首谱面。

谱面是**信号分析辅助、规则编排的试玩谱**。已检查起音图、分段密度和技术约束；尚未逐句人工听审，也没有主张还原原谱、歌词重音或某个角色的具体节奏。设备延迟校准可以抵消输出延迟，不能替代谱面听审。

### 可量化的起音邻近检查

另以高频谱通量的全局阈值筛出 2,157 个参考起音峰：高度 ≥ 第 75 百分位，突出度 ≥ 中位数的 0.4 倍，峰间距 ≥ 60 ms。每颗谱面音符与最近参考峰比较：

| 难度 | 平均绝对距离 | 第 95 百分位 | 30 ms 内 | 60 ms 内 |
| --- | ---: | ---: | ---: | ---: |
| 入门 | 8.954 ms | 34.869 ms | 93.55% | 97.65% |
| 标准 | 8.264 ms | 40.601 ms | 93.11% | 97.65% |

这是**同一录音的瞬态邻近指标**，不是独立人工拍点真值，也不是“节奏准确率”。高频峰可能来自辅音；同一信号参与编排和检查，因此这些数字只能排查明显远离起音的音符。分析时间步长约 5.805 ms，不能把小数位误读为亚毫秒精度。

## 可复现脚本与数据

`experiments/my-shot-rhythm/analysis/build_chart.py` 包含完整流程：

1. FFmpeg 解码、统一采样率，不修改原 MP3。
2. 1,024 点 Hann 窗、128 采样 hop，计算低/中/高频正向对数谱通量。
3. 高频起音归一化；Librosa 动态规划追踪，91 BPM 先验、tightness 1200，避免密集人声造成倍速误判。
4. 计算音色变化曲线，使用已检查的候选边界创建段落。
5. 主拍周围最多约 52 ms 寻找有约束的起音；八分位置最多约 55 ms。四拍手型按规则重复，选入有瞬态依据的八分音符，强乐句开头少量双押。
6. 剔除过近的同轨音符，检查有序性、音轨范围、唯一 ID、时间范围、最多双押、中英标签及输入文件身份。
7. 保存 `chart.json`、`analysis/evidence.json`，可选绘制 `analysis/timing-report.png`。

从 Hamilton 项目根目录运行：

```sh
python3 -m venv --system-site-packages experiments/my-shot-rhythm/analysis/.venv
experiments/my-shot-rhythm/analysis/.venv/bin/python -m pip install -r experiments/my-shot-rhythm/analysis/requirements.txt
experiments/my-shot-rhythm/analysis/.venv/bin/python experiments/my-shot-rhythm/analysis/build_chart.py --plot
python3 experiments/my-shot-rhythm/analysis/validate_chart.py
```

脚本默认读取 `experiments/my-shot-rhythm/public/my-shot.mp3`，可传入另一个**同版本录音**的路径；可通过 `--ffmpeg` 明确指定 FFmpeg。若歌曲、录音版本或音频剪辑改变，旧谱不能直接沿用；校验脚本会比较本地 MP3 的 SHA-256。

`chart.json` 主要字段：

```text
duration             解码后秒数
bpm                  约 91，供展示
offset               首个被追踪脉冲的秒数，不能再次加到 notes.time 上
beats[]              每个追踪主拍的绝对秒数
tempoMap[]           {time, beat, endTime, bpm}，16 拍平均估计
sections[]           {id, start, end, label:{zh,en}, description:{zh,en}, texture}
difficulties.beginner / normal
  notes[]            {id, time, lane:0..3, beat, kind:"tap", accent, source, strength}
analysis             采样参数、音频身份、可信度说明
```

`beat` 是分析网格索引，允许 `.5` 表示八分位置；运行时判定只读 `time`。`source` 为 `pulse`、`eighth-attack` 或 `accent`，供查看与后续听审。结构化校验已通过：同轨间隔至少 235 ms，最多两键同时，没有歌曲之外或最后衰减上的音符。

下一轮听审应优先覆盖两个稀疏段和 60 ms 邻近检查之外的少量音符；由熟悉原声带的人判断哪些起音听起来应当敲击，以及同一乐句是否应更完整复现。

链条：原始 MP3 → 解码后的真实时间 → 起音与主拍 → 音色段落 → 可重复的键盘手型 → 绝对时间谱面 → 音频时钟驱动的画面与判定。
