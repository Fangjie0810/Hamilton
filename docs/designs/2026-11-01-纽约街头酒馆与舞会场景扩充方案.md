# 纽约街头、酒馆与舞会：可探索的音乐剧舞台

日期：2026-11-01。状态：**供团队评审的方案 v0.1，尚未实现或批准为开发规格**。

依据：[两次会议纪要与决策基线](../meetings/README.md)、本次用户的场景扩充意向、当前工作目录的静态源码检查。本文的尺度、人数、演出节奏与优先级均为建议，不是会议已经确认的数字。

## 1. 推荐方向与 Demo 边界

推荐将现有风格发展成“可以走进去的音乐剧舞台”：3D 建筑提供空间，Q 版像素人物承担走位和表演，主像素美术承担对话情绪，Eliza 的书页与旁白连接章节。

三个场景形成递进：**街头让我进入这座城 → 酒馆让我属于这一桌人 → 舞会让我参与两个人的相遇。** 扩充空间时，每个新区域都应有相应的人物活动、视线焦点或探索理由。

| 路线 | 做法 | 收益 | 代价与适用判断 |
|---|---|---|---|
| 推荐：舞台化的可探索 3D 场景 | 街头有城市纵深；酒馆有生活空间；舞会显露木构舞台、群演和灯光调度 | 与现有像素人物一致；空间可复用；音乐、叙事、建模能围绕同一演出设计 | 要认真安排镜头、遮挡和演员走位 |
| 历史写实城市与宴会厅 | 复原大量建筑、室内装饰、服饰和生活细节 | 历史环境更具体 | 研究和资产量较大；与现有像素人物的统一更难，首轮不推荐 |
| 完全镜框式剧场 | 所有内容在固定舞台完成，用换景与灯光推进 | 演出构图可控，资产范围小 | 自由探索感降低，与本次“扩充纽约街头”诉求不完全一致 |

舞美参考采用 David Korins 的设计思路：砖墙、木构、上层廊道、绳索与圆形转台构成可承载多种场景的环境，灯光与调度帮助观众聚焦人物。这些是对设计师访谈的概括；下面的场景布局是本项目的改编建议，并非原剧舞台复刻规格。[设计师访谈，Smithsonian，2018-05-23](https://www.smithsonianmag.com/smithsonian-institution/hamiltons-david-korins-explains-what-makes-smash-hit-design-so-versitle-180969135/)

- 当前 Demo 在《Helpless》婚礼尾声结束。约克镇、更完整人生路线、多视角支线、QTE 和复杂随机彩蛋列入后续池。
- 公开辩论与军营在新 Demo 中的保留方式，会议未说明。建议第一轮白模先以明确标注的过渡占位连接酒馆与舞会，再由蛋花汤的大纲决定哪些事件保留、压缩或转述。
- 上图不表示酒馆与舞会发生于同一晚。转场需要交代时间、身份变化与进入舞会的缘由；相遇与婚礼之间也需要清楚的时间推进。
- 教程曲与已有开场 CG 的衔接尚未决定。优先建议让教程独立成为可交互的序幕段，并评估是否缩短前置观看时间；本轮不直接替换或覆盖已有 CG。
- 先主线和基础剧情，再收藏品，再彩蛋。白模可预留位置，不先建随机事件引擎或要求收集品才能走完主线。

## 3. 统一空间原则

### 3.1 将“充满屏幕”拆成四个可验收问题

1. **世界延续**：默认镜头看不到一圈裸露地台边缘；街道伸向远方，室内以门洞、侧室和上层空间提示场景继续。
2. **可玩密度**：扩大的区域有故事节点、可观察活动或捷径，主线玩家不因扩容增加长时间空跑。
3. **人物可读**：不要为了把建筑全部装进画面而把镜头一直拉远；人物仍能辨认，交谈时能看见关系和动作。
4. **镜头安全**：沿用自由视角与缩放；在允许的极限角度检查地面接缝、背面、墙体遮挡、交互标记和 UI。

世界分三层：近景少量遮挡物／中景可探索区域／远景低成本延续。远景无需碰撞和交互；近景柱、墙、吊灯采用独立遮挡分组，不能整厅一起消失。

### 3.2 首轮白模尺度建议

以下是世界单位的起始假设，不是米，也不是最终工程承诺。按现有角色大小和移动速度实际走查后再锁定。

| 场景 | 当前可走边界 | 首轮建议 | 重点 |
|---|---|---|---|
| 纽约街头 | 40 × 39 | 约 56 × 42 的外包络，内部按建筑切出街路 | 可走边界外包面积约 1.5 倍；视野依靠远景继续扩大 |
| 酒馆 | 22 × 18 | 约 30 × 22 | 外包面积约 1.7 倍；让主桌、吧台、表演区真正分开 |
| 舞会 | 尚无 | 约 36 × 28；中央舞池直径约 16 | 上层回廊首版只作布景，避免立刻增加多层寻路 |

主通道先按两个现有角色可错身行走设计；桌边交互站位需在可走区域，不能因桌面或长凳而隔空触发。保持既有 E 交互距离 1.65、提示显现距离 5.5，先用布局适配距离。

## 4. 纽约街头：让城市在玩家到来前就已运转

目标情绪：陌生、喧闹、充满可能性。颜色沿用黄昏冷蓝环境与门窗暖光，酒馆入口是明确的暖色目的地。

### 空间与动线

- **抵达带**：保留港口／水岸和序幕读信支点，补远处船影、仓库立面、搬货路径。保留可回看的出发方向。
- **主街**：报童—争论—伯尔沿一条易读路线布置；通过建筑退让和街角视线逐步揭示节点，保留已有首次交互与属性教学顺序。
- **酒馆前庭**：入口退进一点，窗内暖光、门外谈话和招牌共同引导。门洞与室内入口在视觉方位上呼应。
- **侧巷小环路**：从主街绕到酒馆后方再回来，容纳原有报纸拾取与未来探索点。首轮只保留一条短支路，避免扩成多条空巷。
- **远景**：对现有 backdrop 增加层次、透视与轮廓变化。高塔、屋顶和船桅形成定位点，不要求全部可达。

活动建议：先做 4–6 名背景居民的稀疏循环，最多两条可移动背景路线；商贩整理货物、两人侧身交谈、搬运工短距离往返。它们不抢主线交互提示，也不挡门口。数量是起步预算，须按实际性能调低或增加。

### 首轮模型与资产

复用现有建筑、码头、摊位与木箱；优先新增一个街角门廊模块、两种可拼接店面立面、一个巷道转角模块、一个远景轮廓组。店面文字以界面／动态贴图本地化，不烘焙单一语言进材质。

### 验收画面

保存同一镜头参数下的抵达点、主街中段、酒馆门前、侧巷回望四组前后对照。默认视角有纵深，玩家不见地台裸边；主要交互可从连续动线完成；酒馆后的报纸可拾取和交还且不会重复奖励。

## 5. 酒馆：由三处问答点改成一桌人的关系

目标情绪：拥挤、热烈、正在发生。入口到主桌形成第一条视线，吧台和壁炉提供侧向生活层次。

### 建议布局

后侧放壁炉、储酒架与备餐门；左侧是吧台和老板；中间偏后是四人长桌；前侧与右侧留下回转通道和《My Shot》小型表演空地。另保留两桌低密度客人，避免所有人物都沿墙排队。

- Hamilton 的进入位置在主桌空位附近。
- Laurens、Lafayette、Mulligan 围同一桌，拥有不同的身体朝向与空闲动作。
- 主线各人交谈仍可选择顺序；不必第一版就把三个交互合并成全新多人对话系统。
- 说话者面向被说话的人，听者转向说话者；结束后回到自己的活动。玩家尚未靠近时，同伴彼此交流。
- 老板擦杯／整理酒瓶；一位陌生人在侧桌；另一桌两位客人低声交谈。首轮增加老板＋约三名背景客人即可。
- 服务员往返作为第二批内容，需要可用走路帧和避让逻辑；首轮可用吧台后的定点动作完成生活感。

### “不盯镜头”的具体实现

像素人物的承载平面仍需面向相机，避免变成薄片；人物画面朝向由世界中的注意对象计算，再交给现有八向素材系统。区分“图像平面可见”与“角色在看谁”。

先用四种行为：自己的空闲活动、听同桌说话、面向玩家交谈、歌曲演出。不要每帧无条件转向玩家。坐姿、碰杯和抬手目前不能假定全部已有，第一轮可用站桌边的既有帧验证关系，确定后再补坐姿和演出动作。

### 《My Shot》如何从生活空间发生

1. 三位同伴的必要交谈完成后，进入同桌的共同回应。
2. 灯光集中到主桌，背景客人停下自己的事；主角站到预留的空地，桌椅不突然穿过人物。
3. 音游进入时，保留场景作为背景；用举杯、转身、点头与短走位回应段落，不让镜头跟每个音符晃动。
4. 在确认的独白前停顿处收尾；回到探索／过渡状态，保留交谈、收藏与完成记录。

演出空地是第一轮的保守选择。桌面跳跃与复杂群舞可后续补，不以新增跳跃物理作为首版依赖。

### 验收

从入口无需跑遍全厅即可读懂“这是一桌同伴”；四人朝向有关系；两侧通路和出口畅通；默认与高俯视下桌椅、吊灯不挡角色；角色脚底和切换帧不漂移；重复进入酒馆不重复发主线奖励。

## 6. 舞会：由群体的热闹聚焦到两个人

目标情绪：期待、相遇、被祝福。舞会做成同一舞台上的社交空间与演出空间，婚礼通过光色、站位和少量可移动布景完成变换。

### 建模结构：五层即可成立

| 层 | 第一轮必需内容 | 后续可加内容 |
|---|---|---|
| 地面 | 木板地台、中央圆形纹理／拼板、外围绕行带 | 两层圆环的独立视觉转动 |
| 后景 | 砖墙、门洞、局部木构支架 | 更丰富的绳索和挂件 |
| 中高层 | 两侧木楼梯、二层回廊与栏杆 | 楼上少量群演；首版不开放玩家登楼 |
| 上方与侧翼 | 烛灯／吊灯、少量布幔、侧光位置 | 更精细的吊灯摆动与灯影 |
| 可移动陈设 | 宾客椅、侧桌、婚礼用的小型陈设 | 更复杂的换景调度 |

场景本身是项目的舞台化改编，不宣称为真实历史宴会地点复原。舞台木构沿用酒馆材质语言；舞会通过更开阔的中央空间、整齐的光区和群体阵型形成差异。

### 人物与素材

新增年轻 Eliza 的场景 Q 版美术是关键依赖；它与脸隐于阴影、执笔整理故事的旁白 Eliza 是两个表现身份。旁白脸部规则保持，不能因此把舞会中的年轻 Eliza 也一律无脸化。

Hamilton、Burr 沿用已有角色；Angelica、Peggy 是否实际出场，以及对应服装、动作和对话范围，由大纲与剪辑确认。第一版先用低细节群演替身验证镜头，不把替身当成正式角色资产。

建议首轮 3–4 对背景舞者，沿用少量动作错开相位。核心动作先做邀请、回应、并步、转身和牵手定格；八向行走素材不能直接等价于双人舞素材。近景牵手需要单独验收，避免手部错位。

### 六个演出状态（暂不写死时间码）

| 状态 | 场景发生什么 | 交互与镜头 |
|---|---|---|
| 入场 | 宾客分散交谈，中央留空，玩家从侧前方进入 | 可探索，保留既有默认俯角与手动镜头 |
| Burr 过渡 | Burr 与相关人物在侧区说话，其他人保持低频活动 | 不生成音符、不计分；无跳键惩罚；明确对话推进方式 |
| 相遇 | 群演让出视线，Eliza 与 Hamilton 成为焦点 | 音游准备；镜头缓慢过渡到固定演出构图 |
| 《Helpless》演出 | 外圈舞者围绕中心变阵，中心双人依段落改变距离 | 默认稳定镜头；轨道／判定区保持屏幕固定，不随世界转动 |
| 婚礼尾声 | 群演站成祝福阵型，中心双人靠近，光色从金蓝收束为暖金与浅蓝 | 建议留最后一个完整乐句供观看，是否无判定由剪辑与试玩决定 |
| Eliza 收束 | 场景定格或缓暗，切入书页与旁白回望 | 写入 Demo 完成点，只结算一次；结束入口文案中英配对 |

“留一个完整乐句观看”是演出建议，不是已确认曲长。舞会到婚礼通过段落与旁白交代时间，不能靠即时换衣让玩家误以为当晚结婚。

### 转台如何控制体量

第一轮仅用圆形地面和舞者沿弧线移动表现旋转感。第二轮可让地面视觉层慢转，但可走平面保持静止；演出时演员按编排定位，避免同时实现平台物理、角色惯性和多层导航。转台是叙事构图的一部分，不要求全程转动。

系统减少动态时取消转台、绕场运镜和持续灯光摆动，用关键姿态与灯光状态替代。暂停时同步冻结演出，不让歌曲暂停而人物继续跳。

### 验收

即使关掉音游界面，观众也能辨认入场、相遇、双人靠近、婚礼收束；开启音游后，判定区不遮中心双人；低画质仍有清楚的光区与轮廓；首版没有必须上楼才能完成的交互。

## 7. 对话框：更像演出字幕与手稿注记

保留主像素美术及其逐句态度系统。建议弱化大面积圆角卡片、均匀装饰线和多层解释标题，将对话区整理成：说话者、小面积情绪肖像、主字幕、副字幕（双语模式才有）。背景使用低干扰深色底或薄纸边，装饰只出现在真正的纸页与章节点。

- 角色对话保持既有主像素美术位置逻辑，先缩减框体和无效留白，不重新生成整套人物。
- Eliza 旁白可用页角、墨线或书页过场连接叙事；不把旁白自动扩展到标题、音游规则和成绩。
- 普通对话仍用左键／空格继续，E 仅作场景交互；不恢复已移除的“下一句”“成长”或底部操作提示。
- 选项保留问题、回应、属性变化与门槛；不重新增加策略副标题。
- 音游进行中避免长段阅读与密集按键同时出现；Burr 过渡作为专门的无判定段。
- 四种语言模式遵守现有规则。一般对话双语，非对话界面按主语言；辩论气泡沿用既有例外。小窗口要检查较长英文与双语高度。

首轮交付两张同一台词的 UI 静态对照即可：当前样式与推荐样式。验证可读性后再改组件，避免同时重写文本、人物和交互。

## 8. 音源、谱面与场景演出接口

先确认录音版本，再确定剪辑，再编谱和精细编排。不能把“独白前停顿”直接转换成猜测的秒数；不同版本可能有不同前奏和停顿。

| 曲目 | 已确认方向 | 待交付 |
|---|---|---|
| Alexander Hamilton | 教程曲，小于 2 分钟 | 音源标识、入点／出点、保留教学段、结尾方式、与已有 CG 的关系 |
| My Shot | 酒馆曲，止于独白前停顿 | 人工确认的具体停顿、剪辑版、谱面重映射、演出结束提示 |
| Helpless | 删去指定对话，保留婚礼结尾 | 需删除的精确片段、删后连接、Burr 过渡对应素材、婚礼保留范围 |

建议统一交付表：`曲目 ID｜源文件与校验值｜段落 ID｜源入点｜源出点｜输出入点｜输出出点｜淡入淡出｜角色／事件｜是否判定｜审核人`。时间码以实际文件为准，曲名不能代替版本标识。

精确段落未锁定时，白模演出以“入场／相遇／合唱／婚礼”等段落 ID 排练，不写假时间码。锁定后，音游判定、人物动作、镜头、灯光都读取同一音频时钟。音乐暂停、失焦、恢复与离开场景必须统一处理；语言切换只改文本，不重置节拍或成绩。

现有完整《My Shot》谱面不能直接裁掉尾部就宣布完成：前奏有删改或重排时要重算输出时间位置；剪辑接缝要人工听审；末尾晚击判定窗口和场景退场要对齐。首轮建议先完成一段短演出与谱面同步，再接整首剪辑版。

## 11. 技术接入与验证清单

场景实现继续使用现有 Three.js 主流程，不创建横版游戏或第二套状态体系。

| 改动 | 接入位置 | 需共同验证的关系 |
|---|---|---|
| 街头扩充 | `World.ts`、`StoryPlaces.ts`、`SceneCatalog.ts` | 地形、边界、碰撞、交互、出生点、出口、发现物坐标一致 |
| 酒馆重排 | `TavernWorld.ts`、`StoryPlaces.ts` | 家具位置、人物站位、朝向、交互顺序、遮挡分组一致 |
| 背景 NPC 与注意对象 | `StoryNpc.ts`、角色调度相关逻辑 | 保留朝向换算与高俯视切图；移动、暂停和消耗另做明确预算 |
| 舞会 | 新增 `BallroomWorld.ts`（建议名称）并接入场景目录 | `SceneId`、章节 ID、章节次序、StoryPlaces、角色目录、完成点、重开与旧存档兼容一起调整 |
| 音游接入 | 复用／提取独立实验的核心能力，经现有活动生命周期接入 | 不直接跳转到独立实验网页；保留退出、暂停和成绩归属 |
| 对话框 | `StoryUI.ts`、`story.css`、现有对话展示组件 | 不破坏 setDialogueText、语言更新、人物态度和配音范围 |

性能先测当前版本再设预算。建议在团队实际设备、同分辨率与同画质下比较帧时间、draw calls、纹理内存和首次进入耗时；目标是常规桌面设备稳定接近 60 fps，较低档位至少有可用的 30 fps 方案。这是待验证目标，当前没有本轮性能测量。

具体控制：继续合批重复木构与砖块；背景人群用共享图集和低频行为；蜡烛优先发光材质，限制实时投影灯；远景不挂昂贵行为；移动转台和动态家具不并入静态块；切场景释放资源。不要提前增加全城路径规划、真实转台物理或每位群演独立 AI。

实施后由开发代理运行 `npm test` 与 `npm run build`（包含 `check:i18n`），音游核心有改动时同时运行对应的 `rhythm:test`、`rhythm:build`。视觉回归覆盖：

- 四种语言；两种双语模式的小窗口；长英文与角色名。
- 默认俯角 `.43`、高俯视切换阈值 `.815`、镜头旋转与缩放极限。
- 交谈—音游—结算、暂停／失焦／继续、章节重开与状态回退、减少动态。
- 存量报纸与发现物奖励不重复；主线退出条件和章节检查点可达。
- 普通幕间 550 ms 渐变、2875 ms 标题等待及减少动态的 250 ms 行为保持既有约定，除非后续明确修改。
- 旁白仅朗读 narrator 的剧情对话；新增人物台词、口型和句后态度有逐句映射。
- 本地验收不自动上线。发布时另走版本升级、CHANGELOG、归档与切换流程。
