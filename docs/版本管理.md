## 版本规则

- `package.json` 是版本号来源。构建前自动生成 `public/version.json`，线上可访问 `/version.json` 查询当前版本。
- 小修复：0.1.1、0.1.2；较大的玩法或内容更新：0.2.0、0.3.0。正式 1.0.0 由用户决定。
- 一个已发布版本只归档一次，不覆盖；更改内容须升级版本号。
- 每次发布更新 `CHANGELOG.md`，记录改动、验证和已知限制。
- 本地改动、构建不自动发布。用户明确要求上线新版本时再上传、安装、切换。

## 本地归档

需要现有 Node/npm 环境与 Python 3.9+（macOS/Linux）。开发代理负责运行以下流程：

```sh
# 将 package.json 更新为下一版本，并编写 CHANGELOG.md 后：
npm run release:pack -- --notes '本次版本具体改动'
```

该命令运行游戏测试、发布工具测试、双语及 TypeScript 检查、生产构建。输出到 `releases/版本号/`：

- `ham-版本号.tar.gz`：游戏网站及版本清单，唯一上传到发布器的包。
- `ham-版本号-source.tar.gz`：代码、依赖锁文件、游戏资源和项目说明快照，留在本地，不公开到网站。
- `release.json`：版本、时间、说明和每个网站文件的 SHA-256。
- `SHA256SUMS`：发布包与源码包校验值。

`releases/` 已被忽略，不加入未来代码仓库；请保留归档目录。源码包是发布时快照，不替代日常 Git 提交历史。

## 服务器布局

```text
/var/www/ham.newflorencia.com/
  current -> releases/0.1.0/site
  releases/
    0.1.0/
      release.json
      site/
        index.html
        version.json
        assets/ ...
  shared/assets/          # 保留历次带哈希文件名的脚本与样式
  history.jsonl           # 登记、安装、切换、失败恢复与回滚记录
  public/                 # 首次上传的原始副本，以及 Certbot 的固定验证目录
```

游戏 HTTPS 站点使用 `current`；HTTP 的 ACME 验证目录继续使用 `public`。Nginx 的 `/assets/` 从 `shared/assets/` 读取，以便发布前打开的标签页仍可下载旧脚本。无哈希文件名的资源采用重新验证缓存，避免更新后继续使用旧图或旧音频。

## 安装新版本

发布工具安装在 `/usr/local/lib/ham-releases.py`，源码位于项目 `scripts/releases.py`。通过 SSH 或已登录的 OrcaTerm 上传网站发布包，然后运行（替换文件路径和真实校验值）：

```sh
python3 /usr/local/lib/ham-releases.py install 0.1.1 /root/ham-0.1.1.tar.gz --sha256 <SHA256SUMS中的发布包校验值>
python3 /usr/local/lib/ham-releases.py activate 0.1.1
python3 /usr/local/lib/ham-releases.py status
```

`install` 检查压缩包校验值、路径安全、版本一致性和文件清单，拒绝覆盖已有版本；不会切换线上版本。`activate` 再次验证文件，通过原子替换符号链接切换版本，然后检查本机 HTTPS 首页与 `/version.json`。检查失败时恢复原链接并记录失败。正常发布不需要修改 Nginx 或重启服务器。

回滚到已有版本：

```sh
python3 /usr/local/lib/ham-releases.py rollback 0.1.0
```

版本管理不改变玩家存档规则。发布或回滚后，玩家刷新页面会按游戏原有规则重新开始主线；不承诺正在游玩的会话能无缝跨版本。大改动应提醒测试玩家完成当前体验后刷新。
