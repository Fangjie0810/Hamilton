# 用户剪辑 CG 接入记录 · 2026-09-11

用户要求将亲自剪辑的 `/Users/fangjie/Movies/9月11日.mov` 放在进入界面与三维开场之间，并让各部分自然衔接。本次是本地实现，没有发布或升级线上版本。

## 素材

- 网页文件：`public/video/opening-2026-09-11.mp4`，约 69 MiB。
- 时长 57.2 秒，1920 × 1080，30 fps，H.264 / yuv420p；AAC 44.1 kHz 立体声。
- 使用 FFmpeg `-map 0:v:0 -map 0:a:0 -c copy -movflags +faststart -map_metadata -1` 无损转封装。没有裁剪、重排镜头、缩放或重编码。
- 原视频从 49.433 秒起进入黑场，音轨持续到片尾。界面在 49.5 秒显露开场标题，不修改原素材黑场和音轨时长。
- 原文件与网页文件的编码视频流、音频流 SHA-256 完全相同，见 `artifacts/intro-review/media-integrity.json`。
- 运行时对最后 550 ms 声音做淡出，跳过时同步淡出当前声音和画面。静音只影响 CG，不改写角色配音偏好。

## 流程与生命周期

进入界面 → 点击启程激活有声媒体 → 同页淡入 CG → CG 上方覆盖期间加载 Three.js、角色和码头，并真正渲染第一帧 → 原片尾黑场接开场标题 → 音轨结束且标题最短等待完成 → 550 ms 揭幕 → 码头读信 → 既有出口与第一幕。

`EntryScreen.ts` 拦截普通启程点击，保留链接原地址与修饰键行为。页面地址通过 History 更新，浏览器后退重新加载相应入口；不使用跨页自动播放或永久的“已看过”标记。

`OpeningFilm.ts` 管理媒体、控件、焦点、音量包络与异步交接。CG 期间 `#app` 为 inert，捕获键盘防止误操作幕后角色。所有新增文字通过 `bi`、`setText`、`setLabel` 更新。切换字幕语言不重建媒体或重置时间。

`Demo.ts` 增加仅初次开场使用的回调；等待场景真正绘制后才交接。回调未完成时沿用 `switching` 阻止玩法推进。初始标题等待由 CG 回调承担，避免重复等待；后续章节、章节重开和直接主线链接仍使用原有 550 / 2875 / 250 ms 参数。

离开窗口或切换标签页暂停影片，需要主动继续；不会在 CG 后意外弹出游戏暂停框。自动播放受限可点击继续，媒体错误可重试／跳过，缓冲超过 1.8 秒提示、12 秒提供明确慢速提示。游戏初始化失败时释放 CG，显示原有游戏错误与重载入口。结束后清除监听器、计时器和媒体源，释放焦点与游戏输入。

## 验证

- `npm test`：69 项核心、状态、剧情、配音测试。
- `npm run build`：包含中英文覆盖与 TypeScript 检查。
- `scripts/opening-film-check.mjs`：实际完整播放；黑场标题与声音交接；真正 ended 后释放玩法；暂停、静音、失焦、三种语言、小窗口；自然结束后的读信与第一幕；提前跳过、媒体失败、自动播放拒绝恢复。
- `scripts/entry-check.mjs`：九组语言／窗口布局、设置保存、键盘启程、CG 跳过、游戏设置继承与返回入口。
- `scripts/chapter-transition-check.mjs`：既有章节实际生命周期、图片回退、语言布局与对比度。
- 画面与检查报告位于 `artifacts/intro-review/`；回归在本机 Chrome 完成，不代表其他浏览器或真实慢速网络已实测。

未来更换剪辑时必须重新检查时长与尾部黑场，再调整 `TITLE_CUE_SECONDS`；不要直接沿用 49.5 秒的交接点。
