## 新版本到位后的执行模板（现在不执行）

### 1. 确认唯一正式版本并归档

以届时工作区 `package.json` 为唯一版本来源，汇总最终内容更新与性能更新，补齐 `CHANGELOG.md`。执行既有 `npm run release:pack -- --notes '最终实际变更说明'`，保留网站包、源码包及 SHA-256 清单，规则沿用 [版本管理](版本管理.md)。本次未在工作区新增正式 0.2.1 发布归档。

此前的 `/private/tmp/ham-cdn-release-0.2.1` 和 `/private/tmp/hamilton-cos-upload` 都是中断前的临时性能验证草稿，已放置 `NOT_FOR_UPLOAD.txt`，**不得当作用户准备好的新版上传**。临时目录也不能作为持久归档依赖。

### 2. 上传正式网站内容并核验

仅上传正式网站内容到 COS，源码归档不公开。对象路径使用：

```text
releases/<最终版本>/site/index.html
releases/<最终版本>/site/version.json
releases/<最终版本>/site/video/...
releases/<最终版本>/site/audio/...
releases/<最终版本>/site/其他实际构建文件
shared/assets/<带哈希文件名的脚本和样式>
```

保留所有旧版本目录，不覆盖已有归档；共享哈希资源追加新文件，同名已存在文件须校验一致，不能直接覆盖。首次迁移时还应从已验证的 0.2.0 发布包补入旧哈希资源。需要核验文件清单、大小和 SHA-256，不能只看上传进度完成。

对象元数据：HTML/JSON 使用 `Cache-Control: no-cache`；带哈希的脚本样式可设 `public,max-age=31536000,immutable`；没有内容哈希的资源使用 `public,max-age=0,must-revalidate`，浏览器每次重新验证，CDN 节点缓存仍由上述 30 天规则控制。媒体分别为 `video/mp4`、`audio/mpeg`；HTML/CSS/JS/JSON 设置正确 MIME，不允许统一成为附件下载。上线验证同时检查 CDN 最终响应头及二次请求节点缓存命中，不能只依赖控制台设置。无浏览器覆盖规则时，源站的 `Cache-Control` 会传给浏览器。[浏览器缓存说明](https://cloud.tencent.com/document/product/228/50114)

### 3. 绑定最终版本的回源规则

源站 Host 统一保持 `hamilton-site-1312715323.cos.ap-guangzhou.myqcloud.com`。建议按以下顺序从上到下配置，底部优先级高：

| 待重写 URL | 匹配方式 | 目标回源 Path |
| --- | --- | --- |
| `/*` | 通配符 | `/releases/<最终版本>/site/$1` |
| `/assets/*` | 通配符 | `/shared/assets/$1` |
| `/` | **全路径匹配** | `/releases/<最终版本>/site/index.html` |

`<最终版本>` 是待替换模板，不能原样提交。`/` 必须选择全路径匹配，避免把所有请求改成首页。腾讯云支持通配符和捕获占位符，底部规则优先；此模板尚未进行真实对象回源验收。[回源 URL 重写说明](https://cloud.tencent.com/document/product/228/50110)

更新回源目录不会自动改变浏览器看到的资源 URL。正式切换时刷新所有可能沿用原 URL 的旧 CDN 内容；预热新 CG 和主要资源。检查旧哈希 JS、查询参数、嵌套音频路径都能正确获取，确保 HTML 不会误返回给媒体请求。

### 4. 证书、上线前验证与切换

用户提供证书后检查覆盖 `ham.newflorencia.com`、有效期、证书链和密钥匹配，通过控制台配置；不在文档或聊天中记录私钥。随后开启 HTTP/2、强制 HTTPS 和 OCSP，核验 TLS。证书续期方法须随实际证书来源确定；域名迁移到 CDN 后，原服务器的 HTTP-01 验证不会自动抵达服务器，不能假定旧自动续期继续有效。

DNS 保持旧 A 记录期间，通过指定 CDN 边缘地址并保留 `ham.newflorencia.com` 的 Host/SNI 做上线前验证：HTTPS 有效、首页/版本正确、主要脚本和音频无 403/404、CG Range 返回 206 且范围/大小正确、二次请求有缓存证据、四语言和完整主流程通过。私有 COS 裸地址拒绝匿名读取是预期，不能当作 CDN 失败。

全部通过后，将 **ham 这一条** A 记录替换为分配的 CNAME，保留 TTL 600，其他子域名不动。域名解析传播后复查实际 CDN 命中、CG 起播及持续播放。此时才记录 CDN 上线成功。

### 5. 回退

保留原服务器及 0.2.0 独立版本归档。若上线异常，先将 ham 恢复为 A `159.75.67.184`，TTL 600，并核验旧 HTTPS/版本；DNS 回退受缓存传播影响，不是瞬时切换。服务器若以后安装新版，仍须用既有发布工具的 `install` / `activate` / `rollback`，不得直接写入 `current` 或覆盖归档。

执行链：**新版就绪 → 正式归档 → 上传并校验 → 绑定版本目录与证书 → CDN 实际验收 → 切换 ham DNS → 复查，异常则回退。**
