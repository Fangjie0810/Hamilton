# Hamilton 部署指导

编写日期：2026-10-18（Asia/Shanghai）。适用域名：`ham.newflorencia.com`。

采用个人主页项目的 **`ssh bio-home` 公钥连接方式**，通过 SSH/SCP 上传 Hamilton 发布包，再使用 Hamilton 现有发布工具安装、切换与回滚。命令由开发代理执行；需要用户处理的仅是代理无法完成的账号验证或授权。

本文件是操作指南，不是上线记录。本次没有连接服务器、上传文件、切换版本或修改 DNS。

## 依据与适用范围

- 连接方法来自 [个人主页服务器连接说明](../../个人主页%20bio.newflorencia.com/服务器连接说明.md)。该文件记录的是连接准备，明确注明尚未部署主页，并没有可直接照搬的网站发布流程。
- Hamilton 发布规则来自 [版本管理](版本管理.md)，实际命令以 [scripts/releases.py](../scripts/releases.py) 为准。
- [2026-09-13 部署记录](部署记录-2026-09-13.md) 中 Hamilton 的服务器 IP 与个人主页连接入口一致：`159.75.67.184`。这是历史记录，实际发布前仍须核对服务器与公网入口。
- [CDN 上线准备记录](CDN上线准备-2026-09-14.md) 是另一条迁移路线。若届时公网已经切到 COS/CDN，只更新这台服务器不会更新 CDN 网站，应按 CDN 指南处理；本指南不包含 DNS 或 CDN 切换。

复用连接入口不改变项目边界：只操作 Hamilton 的目录、发布工具和域名，不向个人主页目录上传游戏，也不修改其他站点。

## 二、发布前核对

用户明确要求发布更新后，先核实目标和回退点。以下检查不安装或切换版本：

```sh
cd '/Users/fangjie/Documents/Codex 项目/Hamilton'
node -p 'require("./package.json").version'
dig +short ham.newflorencia.com CNAME
dig +short ham.newflorencia.com A
curl --fail --silent --show-error --max-time 20 https://ham.newflorencia.com/version.json
ssh -o BatchMode=yes bio-home 'sudo -n test -f /usr/local/lib/ham-releases.py && sudo -n python3 /usr/local/lib/ham-releases.py status'
ssh -o BatchMode=yes bio-home 'readlink /var/www/ham.newflorencia.com/current; df -h /var/www; sudo -n nginx -t'
```

记录公网版本、`current` 目标、已安装版本及剩余空间。发布包、解压后网站和保留的历史版本都需要空间。域名解析与版本号只是初步证据；如与历史记录不同，应核对实际站点配置和流量入口后再选择发布路线。

本地 `package.json` 在编写时为 `0.5.2`，且已有同名归档；这不代表线上也是 `0.5.2`。不要覆盖该归档，也不要把之后的改动重新包装成同一版本。

如发布工具缺失、`current` 不是符号链接、站点配置不同或证书不可用，先解决具体差异。本指南假设已有 Hamilton 站点可正常运行，不适用于空服务器首次初始化。不得为继续执行而临时创建 `current`、替换其他站点配置或跳过 HTTPS 检查。

## 三、本地验证与归档

1. 汇总要发布的改动，升级 `package.json` 版本并更新 `CHANGELOG.md`。
2. 按 README 验证三维主线、四种语言、两种双语小窗口，以及本次涉及的功能。
3. 运行正式归档命令，将说明替换为本次实际内容：

```sh
npm run release:pack -- --notes '本次版本具体改动'
```

该命令依次执行 `npm test`、`npm run test:releases` 和 `npm run build`；构建包含双语检查、TypeScript 检查及 Vite 构建。任何失败都应修复后重试，不跳过检查。

生成的 `releases/<版本>/` 包含网站包、源码包、`release.json` 和 `SHA256SUMS`。网站包上传服务器，源码包留在本地归档，不公开。归档后如继续修改待发布内容，应重新确定版本，不能覆盖已存在的归档。

## 四、上传与安装（尚不切换）

下面命令在同一个本地终端会话中执行。上传目录使用 Hamilton 专属路径；所有命令成功后才进入下一步。

```sh
cd '/Users/fangjie/Documents/Codex 项目/Hamilton'
HAM_VERSION=$(node -p 'require("./package.json").version')
HAM_RELEASE_DIR="releases/$HAM_VERSION"
HAM_ARCHIVE="ham-$HAM_VERSION.tar.gz"

# 校验网站包和源码包与归档清单一致。
(cd "$HAM_RELEASE_DIR" && shasum -a 256 -c SHA256SUMS)
HAM_SHA256=$(shasum -a 256 "$HAM_RELEASE_DIR/$HAM_ARCHIVE" | awk '{print $1}')

ssh -o BatchMode=yes bio-home "mkdir -p /home/ubuntu/hamilton-uploads/$HAM_VERSION"
scp -o BatchMode=yes "$HAM_RELEASE_DIR/$HAM_ARCHIVE" "bio-home:/home/ubuntu/hamilton-uploads/$HAM_VERSION/$HAM_ARCHIVE"

ssh -o BatchMode=yes bio-home "sudo -n python3 /usr/local/lib/ham-releases.py install $HAM_VERSION /home/ubuntu/hamilton-uploads/$HAM_VERSION/$HAM_ARCHIVE --sha256 $HAM_SHA256"
ssh -o BatchMode=yes bio-home 'sudo -n python3 /usr/local/lib/ham-releases.py status'
```

`install` 验证网站包 SHA-256、压缩包路径安全、版本一致性和逐文件清单，再写入独立的 `releases/<版本>/site`，拒绝覆盖已有版本。此时应确认新版本已安装、`current` 仍指向旧版本。

SSH 中断后先查询 `status`，再判断是重新上传还是继续操作；不要删除已有版本来绕过重复安装错误。正常更新使用服务器已有发布工具，不自动覆盖 `/usr/local/lib/ham-releases.py`。

## 五、切换与验收

发布授权涵盖上线、安装检查通过且已记录旧版本后，在同一个终端会话中执行：

```sh
ssh -o BatchMode=yes bio-home "sudo -n python3 /usr/local/lib/ham-releases.py activate $HAM_VERSION"
ssh -o BatchMode=yes bio-home 'sudo -n python3 /usr/local/lib/ham-releases.py status'
curl --fail --silent --show-error --max-time 20 https://ham.newflorencia.com/version.json
```

`activate` 再次核验文件，原子切换 `current`，通过本机 HTTPS 检查首页与版本号；检查失败会恢复旧链接并记录失败。这只覆盖服务器本机检查，不能替代公网及浏览器验收。

开发代理继续验证：

- 公网 HTTPS 证书有效，首页及 `/version.json` 对应目标版本；主要脚本、样式、音频与 CG 正常返回，抽查实际资源与发布清单校验值。
- 实际打开线上游戏，确认标题页、启程、CG 起播与跳过、三维序幕及本次修改功能；检查四语言和两种双语的小窗口布局。
- 核对旧的带哈希脚本仍可获取、无新增控制台错误或资源失败。正常版本切换无需修改 Nginx 或重启服务器。

服务器目录保持：

```text
/var/www/ham.newflorencia.com/
  current -> releases/<当前版本>/site
  releases/<版本>/release.json
  releases/<版本>/site/
  shared/assets/
  history.jsonl
  public/
```

不直接向 `current` 写文件，不覆盖历史版本，不清空共享资源。`public/` 仍承担既有 ACME 验证目录用途。

## 六、回滚与记录

若公网或实际游玩验收失败，使用发布前记录并确认存在的旧版本。下列占位值必须替换后执行：

```sh
HAM_PREVIOUS_VERSION='替换为发布前记录的旧版本号'
ssh -o BatchMode=yes bio-home "sudo -n python3 /usr/local/lib/ham-releases.py rollback $HAM_PREVIOUS_VERSION"
ssh -o BatchMode=yes bio-home 'sudo -n python3 /usr/local/lib/ham-releases.py status'
curl --fail --silent --show-error --max-time 20 https://ham.newflorencia.com/version.json
```

回滚后再次做公网与浏览器验收；保留失败版本和日志供排查。服务器版本回滚不会自动回退 DNS 或 CDN。发布或回滚也不保证正在游玩的会话无缝跨版本，测试玩家需按通知刷新。

完成后新增 `docs/部署记录-YYYY-MM-DD.md`，同日多次发布可附版本号，记录：发布时间、目标与旧版本、网站包校验值、安装与切换结果、公网及浏览器验证证据、已知限制和可用回退点。不得把仅上传成功写成上线验收成功。

执行链：核对 SSH 与实际入口 → 确认版本和回退点 → 测试构建与双归档 → SCP 上传 → 校验安装 → 原子切换 → 公网与实际游玩验收 → 记录，异常则回滚并复验。
