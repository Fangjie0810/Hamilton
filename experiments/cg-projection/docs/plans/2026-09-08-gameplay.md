# 玩法补齐 · 2026-09-08

用户已确定优先补齐玩法。本轮依序实现、验证 M2 辩论，再实现 M3 约克镇，补上规格中未单列里程碑的 Writing 与酒馆限时回应。美术与分层音乐仍按后续阶段处理。

沿用六幕、StateSystem、章节检查点和 DOM 界面。新增小游戏使用纯 TypeScript 状态机处理时间、输入与成绩，界面由 Phaser 场景 update 驱动；暂停、失焦停止计时，场景退出清理界面和输入。结算通过 StateSystem.choose 防止重复入账。无需后端或新依赖。

相比直接扩展对话选择，此方案能独立验证节拍与阶段状态；相比新增完整游戏框架，复用现有场景与移动即可，不新增场景路由。

1. Debate：原创六组论点，阅读后启动 2.5 秒选牌，FACT / PRINCIPLE / ATTACK / CROWD，±100 / ±250 ms 判定，Flow、群众支持、可信度、风格影响 Burr；达标或轮次耗尽进入结算。
2. Yorktown：横向移动、蹲伏、士兵跟随/待命、可见守卫视野与掩体；抵达后为三队部署 HOLD / ADVANCE / FLANK，敌军警戒、士气和位置反馈；最后执行节拍指令。错误扣分但继续，成绩来自实际三阶段表现。
3. Writing：三份军令、每份五类碎片，拖拽或键盘/点击分配 PRIORITY / ACTION / CONTEXT；允许提交不完整稿件并反馈纠正，有限轮次保证剧情可继续；准确率影响 Trust。
4. Tavern：读完问题后开始 5 秒，超时记录沉默，不替玩家选择立场；暂停冻结倒计时。
5. 回归：纯逻辑边界与两条端到端路线（高表现/失误继续），覆盖暂停、重开、重复输入、结果保存、键盘和鼠标、较小窗口；每阶段 build，最后更新 README 与开发记录。

参数按规格给出默认值。实际阅读与游玩时长需要首次玩家计时验证，不以自动化运行速度作结论。节拍提供视觉与短提示音；完整五层配乐不包含在玩法实现中。
